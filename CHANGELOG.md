# Changelog

## 0.5.0 — 2026-08-12

Паритет с iOS SDK 0.5.0. Минор, а не патч: добавлена функциональность — события
прохождения воронки наружу, встроенный показ квиза, profile-id подписочных
платформ в URL страницы.

- **События воронки из WebView-моста** — `setFunnelEventListener { name, data -> }`.
  Наружу идут `quiz_start`, `quiz_screen_view`, `quiz_answer`,
  `quiz_email_submit`, `quiz_complete`, а также `paywall_result` со
  `status = "dismissed"`. Слушатель один на SDK, снимается передачей `null`;
  колбэк доставляется на главный поток.
- ⚠ **Изменение поведения моста.** Раньше ЛЮБОЕ распознанное событие моста
  закрывало встроенный WebView. Теперь закрывают ровно два —
  `paywall_result` со `status = "success"` и `close`; всё остальное (включая
  `paywall_result:dismissed` и все `quiz_*`) окно не трогает. Незнакомые события
  игнорируются, поэтому старые интеграции работают без правок.
- **`openQuizEmbedded(context, quizUrl, email) { result -> }`** — открытие квиза
  встроенным WebView (тот же экран и тот же мост, что у пейволла). Принимает
  ГОТОВЫЙ URL квиза: ручки резолва URL по ID на бэкенде нет, аналога
  `openWebPaywallEmbeddedById` тут не существует. Результат — не оплата, а факт
  закрытия: `QuizResult.Closed(reason)` с `QuizCloseReason.PAGE` / `USER` /
  `PAID`, либо `QuizResult.Unavailable` (SDK не сконфигурирован — экран не
  показали). Событие `quiz_complete` окно НЕ закрывает: квиз ведёт дальше.
  Право в квиз-режиме SDK не поллит — за грантом идите в `entitlement`.
- **profile-id подписочных платформ в URL** — у всех методов открытия (и
  пейволла, и квиза) появились необязательные `adaptyProfileId` /
  `revenuecatProfileId`. SDK дописывает их в URL страницы как
  `adapty_profile_id` / `revenuecat_profile_id`; связку с guid делает сервер сам,
  отдельную ручку звать не надо.

### ⚠ Ломающее для интеграторов (компилятор поймает, молча не сломается)

- **Позиционный колбэк в методах открытия.** Оба profile-id встали ПЕРЕД
  `onResult` / `onClose`. Вызов трейлинг-лямбдой —
  `openWebPaywall(context, url, email) { ... }` — как работал, так и работает.
  А вызов, где колбэк передавался позиционно четвёртым аргументом —
  `openWebPaywall(context, url, email, callback)` — перестанет компилироваться:
  четвёртый аргумент теперь `adaptyProfileId: String?`. Чинится трейлинг-лямбдой
  или именованным аргументом (`onResult = { ... }`).
- **Вызовы из Java со всеми аргументами.** У методов открытия нет
  `@JvmOverloads`, поэтому из Java виден единственный перегруз — с полным
  списком параметров, и его сигнатура изменилась. Передавайте `null` в оба
  profile-id.
- (уже было в 0.4.3, но напоминаем — если обновляетесь с 0.4.0) у
  `PaywallResult` появился вариант `Unavailable`; исчерпывающий `when` без
  `else` требует новой ветки.

## 0.4.3 — 2026-08-12

Паритет с iOS SDK 0.4.3. Номер выровнен с эталоном: координата публикации
(`build.gradle.kts`, README) отставала на `0.1.0`, пока changelog уже шёл по 0.4.x.

- **Починен парс ответа `GET /public/handoff/resolve?code=`**: guid лежит внутри
  обёртки `{"success":true,"data":{...}}`, а читался с верхнего уровня. Из-за
  этого `identify()` и `identifyWithDeepLinkValue()` не работали вообще —
  теперь работают (проверено на живом проде).
- ⚠ **Потенциально ломающее изменение:** у `PaywallResult` появился четвёртый
  вариант — `Unavailable` («пейволл не показали»: SDK не сконфигурирован или URL
  по `paywallId` не зарезолвился) — отдельно от `NotPaid` («показали, но оплату
  не подтвердили»). Исчерпывающий `when` по `PaywallResult` без `else`
  перестанет компилироваться, пока не добавите ветку.
- Окно поллинга права после закрытия встроенного пейволла — 10 попыток по 1 с
  для всех исходов, включая нативное закрытие крестиком (было 2 попытки).
- Все колбэки публичных методов (включая `onNeedEmail` и ранние возвраты)
  доставляются на главный поток: на главном — синхронно, иначе `Handler.post`.
- Новый встроенный показ вытесняет предыдущий — два пейволла одновременно не
  висят, колбэк вытесненного закрывается.
- `debugSetGuid` / `debugClear` помечены `@Deprecated` (WARNING). В Android
  библиотека не видит `BuildConfig.DEBUG` приложения, поэтому аналога
  iOS-обрезки `#if DEBUG` нет — предупреждение компилятора заменяет её.
  Методы остаются рабочими, поведение не изменилось.
- CI: `.github/workflows/ci.yml` — `./gradlew test` на JDK 17 (push + PR).

## 0.4.0 — 2026-07-27

Паритет iOS SDK 0.4.x (WEB-814):

- `openWebPaywallById` / `openWebPaywallEmbeddedById` — открытие пейволла по ID
  из кабинета (резолв публичного URL через `GET /public/paywall-url/:paywallId`).
- `openWebPaywallEmbedded` — встроенный показ (full-screen WebView + JS-мост
  `web2appBridge`): авто-закрытие на успехе оплаты, кнопка «Закрыть» страницы
  идёт мостом, нативный крестик-фолбэк (frosted-стиль, как iOS 0.4.3).
- `PaywallResult` — типизированный результат: `Paid(grant)` / `NotPaid` /
  `Pending` (окно истекло, доступ может доехать позже).

## 0.3.0 — 2026-07-27

Паритет iOS SDK 0.3.0 (WEB-813):

  intent-filter и схемы в кабинете.
