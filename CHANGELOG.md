# Changelog

## [0.7.2]

Встроенный показ (`openWebPaywallEmbedded`, `openWebPaywallEmbeddedById`,
`openQuizEmbedded` — у них один экран). Существующие вызовы не меняются;
у `configure` добавлен необязательный последний параметр `warmUpWebView`.

### Fixed
- **Поворот экрана больше не считается закрытием.** Экран встроенного показа не
  пересоздаётся при повороте, смене темы и клавиатуры (`configChanges` в
  манифесте библиотеки): страница не грузится заново, колбэк не уходит раньше
  времени. Страховка: если экран всё же пересоздан системой, колбэк «закрыли»
  не отдаётся, новая копия экрана доигрывает показ (в журнале —
  `paywall.recreated_on_config_change`).
- **Гибель процесса страницы не роняет приложение (Android 8.0+).** Раньше
  падение или выгрузка рендерера WebView убивали всё приложение интегратора.
  Теперь SDK убирает погибший WebView и создаёт новый с той же страницей; показ
  закрывается с `PaywallResult.Unavailable` / `QuizResult.Unavailable` после
  двух падений подряд (без успешной загрузки между ними) или на шестом падении
  за показ; работает на Android 8.0+. Счётчики живут, пока жив экран показа.
  Выгрузка процесса системой ради памяти (обычно в
  фоне, пока человек подтверждает оплату в банке) падением не считается и в
  лимит не идёт. Если экран не на переднем плане, страница грузится заново при
  возврате на него, а не сразу. У пейволла перед `Unavailable` проверяется
  право тем же окном, что при обычном закрытии (до ~10 секунд): если оплата
  успела пройти — `Paid`. В журнале — `paywall.webview_process_terminated`
  (падение), `paywall.webview_process_reclaimed` (выгрузка системой) — оба с
  `didCrash`, `rendererPriorityAtExit` и `inForeground` — и
  `paywall.webview_process_terminated_twice`, а при исчерпании потолка за показ —
  `paywall.webview_process_crash_limit` (поле `total`).

### Added
- **Индикатор загрузки вместо белого экрана.** Системный индикатор по центру,
  пока страница не загрузилась. Ошибка загрузки страницы прячет индикатор и
  пишется в журнал (`paywall.webview_load_failed` с кодом ошибки); крестик
  остаётся. Надписей SDK не добавляет.
- **Прогрев движка WebView и кэш адреса пейволла.** `configure` один раз
  прогревает движок WebView (только в основном процессе приложения; сбой —
  `paywall.webview_warmup_failed`), поэтому первый показ открывается быстрее.
  Прогрев стоит сотни миллисекунд главного потока при запуске; выключается
  новым необязательным параметром `configure(..., warmUpWebView = false)`
  (по умолчанию `true`, прежние вызовы не меняются). Пропуск прогрева пишется
  `paywall.webview_warmup_skipped` с причиной `not_main_process` (не основной
  процесс приложения) или `disabled_by_config` (выключен параметром).
  `WebView.setDataDirectorySuffix` нужно звать до `configure`.
  `openWebPaywallEmbeddedById` помнит адрес пейволла час и повторно не ходит за
  ним в сеть (попадание в кэш — `paywall.resolve_url_cached`); кэш сбрасывается
  при `configure` и смене guid.

### Changed
- Версия в журнале SDK (`sdkVersion`) снова совпадает с версией библиотеки: в
  0.7.1 журнал называл себя 0.7.0. Их совпадение теперь проверяет тест.

### Не входит
- Предзагрузки пейволла заранее, как в iOS 0.8.0, в Android нет — по решению
  владельца.

## [0.7.1] — 2026-08-14

### Changed
- **Окно попыток опознания по отпечатку — 2 часа с первой неудачи (WEB-1384).**
  Слепок на сервере живёт максимум 2 часа, поэтому после истечения окна
  `identify()` больше не ходит в сеть за отпечатком и сразу отдаёт
  email-фолбэк (в журнале — `identify.fingerprint_window_expired`). Повторные
  попытки ВНУТРИ окна сохранены: «увидел email-экран → закрыл → вернулся через
  10 минут» по-прежнему склеивается. Зеркало iOS 0.7.1.

## 0.7.0 — 2026-08-13

Паритет с iOS SDK 0.7.0. Версии 0.6.0 на Android не было: номер прыгает
0.5.0 → 0.7.0, чтобы выровняться с iOS-эталоном; обе iOS-фичи (0.6.0 и 0.7.0)
входят в этот один релиз. Публичная поверхность SDK не изменилась — ломающих
изменений нет.

### Added

- **Удалённый журнал SDK (паритет iOS 0.6.0).** Каждый внутренний шаг SDK —
  `configure`, ветки `identify` (кэш-guid / Install Referrer: получен, пуст,
  недоступен / резолв токена / email-fallback), запрос права, открытие
  пейволла/квиза, события JS-моста (`funnel.*`), возвратный deep-link,
  APP_INSTALLED-callback и все ошибки сети с HTTP-кодами — теперь пачками
  отправляется на наш бэкенд (`POST /public/sdk-logs`) и дублируется в Logcat
  (тег `Web2App`). Это диагностика интеграций: раньше «что происходит внутри
  приложения интегратора» было видно только по его логам Logcat. Отправка
  fire-and-forget с дебаунсом 3 с, капом буфера (200 записей) и пачками ≤ 50 —
  сбой сети или бэкенда никак не влияет на работу SDK. PII не уходит: email не
  логируется (только факт «email передан»), guid — наш собственный client-held
  идентификатор. Имена событий общие с iOS — журнал у платформ один.
- **Бесшовное опознание по отпечатку устройства (WEB-1213, паритет iOS 0.7.0).**
  `identify()` перед email-фолбэком пробует получить guid по отпечатку:
  приложение отправляет сигналы устройства (версия Android, модель, экран в
  логических dp, таймзона, язык) на `POST /public/handoff/resolve-by-fingerprint`;
  сервер отвечает guid только при **единственном уверенном совпадении** с
  сигналами, которые веб-страница оставила в момент ухода покупателя в стор.
  Любой промах — прежний email-фолбэк, поведение не хуже старого. Закрывает
  сценарий «Install Referrer пуст или недоступен» (Huawei/sideload/органика
  после клика по возвратной ссылке). Никаких рекламных идентификаторов (ни
  GAID, ни ANDROID_ID). В журнале SDK видно: `identify.fingerprint_attempt` →
  `identify.fingerprint_matched` (с `matchMethod`) или
  `identify.fingerprint_no_match`.

### Changed
- **Уточнено поведение связки `guid` ↔ profile-id на стороне сервера** (только
  документация; поведение SDK не менялось). Страница пишет значение лишь в
  ПУСТОЙ слот: заменить уже сохранённое через страницу нельзя (только серверной
  ручкой `POST /s2s/v1/identity/link-profile`), а дописать вторую платформу
  можно только вместе с верными значениями всех уже занятых слотов. Отказ
  молчаливый — сервер отвечает «успех» в любом случае (защита от перебора
  плательщиков). **Рецепт для интеграторов:** передавать ОБА идентификатора
  (`adaptyProfileId` и `revenuecatProfileId`) при КАЖДОМ открытии страницы —
  прежние формулировки «связку делает сама страница, звать ничего не нужно» и
  «связка пишется один раз (первая запись побеждает)» (запись 0.5.0 ниже и
  README) вводили в заблуждение. Отдельно: наш `guid` нельзя использовать как
  profile-id платформы (`Purchases.logIn(<guid>)`) — с ним дозапись второй
  платформы через страницу не сработает никогда.
- **Уточнён doc-комментарий `identifyWithDeepLinkValue`**: токен опознания лежит
  в `deep_link_sub1` (дубль — `af_sub1`), а в `deep_link_value` бэкенд кладёт
  константу `handoff`.

## 0.5.0 — 2026-08-12

Паритет с iOS SDK 0.5.0. Минор, а не патч: добавлена функциональность — события
прохождения воронки наружу, встроенный показ квиза, profile-id подписочных
платформ в URL страницы.

- **События воронки из WebView-моста** — `setFunnelEventListener { name, data -> }`.
  Наружу идут `quiz_start`, `quiz_screen_view`, `quiz_answer`,
  `quiz_email_submit`, `quiz_complete`, а также `paywall_result` со
  `status = "dismissed"`. Слушатель один на SDK, снимается передачей `null`;
  колбэк доставляется на главный поток.
- ⚠ **Изменение поведения моста.** Раньше ЛЮБОЕ распознанное событие моста
  закрывало встроенный WebView. Теперь закрывают ровно два —
  `paywall_result` со `status = "success"` и `close`; всё остальное (включая
  `paywall_result:dismissed` и все `quiz_*`) окно не трогает. Незнакомые события
  игнорируются, поэтому старые интеграции работают без правок.
- **`openQuizEmbedded(context, quizUrl, email) { result -> }`** — открытие квиза
  встроенным WebView (тот же экран и тот же мост, что у пейволла). Принимает
  ГОТОВЫЙ URL квиза: ручки резолва URL по ID на бэкенде нет, аналога
  `openWebPaywallEmbeddedById` тут не существует. Результат — не оплата, а факт
  закрытия: `QuizResult.Closed(reason)` с `QuizCloseReason.PAGE` / `USER` /
  `PAID`, либо `QuizResult.Unavailable` (SDK не сконфигурирован — экран не
  показали). Событие `quiz_complete` окно НЕ закрывает: квиз ведёт дальше.
  Право в квиз-режиме SDK не поллит — за грантом идите в `entitlement`.
- **profile-id подписочных платформ в URL** — у всех методов открытия (и
  пейволла, и квиза) появились необязательные `adaptyProfileId` /
  `revenuecatProfileId`. SDK дописывает их в URL страницы как
  `adapty_profile_id` / `revenuecat_profile_id`; связку с guid делает сервер сам,
  отдельную ручку звать не надо.

### ⚠ Ломающее для интеграторов (компилятор поймает, молча не сломается)

- **Позиционный колбэк в методах открытия.** Оба profile-id встали ПЕРЕД
  `onResult` / `onClose`. Вызов трейлинг-лямбдой —
  `openWebPaywall(context, url, email) { ... }` — как работал, так и работает.
  А вызов, где колбэк передавался позиционно четвёртым аргументом —
  `openWebPaywall(context, url, email, callback)` — перестанет компилироваться:
  четвёртый аргумент теперь `adaptyProfileId: String?`. Чинится трейлинг-лямбдой
  или именованным аргументом (`onResult = { ... }`).
- **Вызовы из Java со всеми аргументами.** У методов открытия нет
  `@JvmOverloads`, поэтому из Java виден единственный перегруз — с полным
  списком параметров, и его сигнатура изменилась. Передавайте `null` в оба
  profile-id.
- (уже было в 0.4.3, но напоминаем — если обновляетесь с 0.4.0) у
  `PaywallResult` появился вариант `Unavailable`; исчерпывающий `when` без
  `else` требует новой ветки.

## 0.4.3 — 2026-08-12 (тег не публиковался, изменения вошли в 0.5.0)

Паритет с iOS SDK 0.4.3. Номер выровнен с эталоном: координата публикации
(`build.gradle.kts`, README) отставала на `0.1.0`, пока changelog уже шёл по 0.4.x.

- **Починен парс ответа `GET /public/handoff/resolve?code=`**: guid лежит внутри
  обёртки `{"success":true,"data":{...}}`, а читался с верхнего уровня. Из-за
  этого `identify()` и `identifyWithDeepLinkValue()` не работали вообще —
  теперь работают (проверено на живом проде).
- ⚠ **Потенциально ломающее изменение:** у `PaywallResult` появился четвёртый
  вариант — `Unavailable` («пейволл не показали»: SDK не сконфигурирован или URL
  по `paywallId` не зарезолвился) — отдельно от `NotPaid` («показали, но оплату
  не подтвердили»). Исчерпывающий `when` по `PaywallResult` без `else`
  перестанет компилироваться, пока не добавите ветку.
- Окно поллинга права после закрытия встроенного пейволла — 10 попыток по 1 с
  для всех исходов, включая нативное закрытие крестиком (было 2 попытки).
- Все колбэки публичных методов (включая `onNeedEmail` и ранние возвраты)
  доставляются на главный поток: на главном — синхронно, иначе `Handler.post`.
- Новый встроенный показ вытесняет предыдущий — два пейволла одновременно не
  висят, колбэк вытесненного закрывается.
- `debugSetGuid` / `debugClear` помечены `@Deprecated` (WARNING). В Android
  библиотека не видит `BuildConfig.DEBUG` приложения, поэтому аналога
  iOS-обрезки `#if DEBUG` нет — предупреждение компилятора заменяет её.
  Методы остаются рабочими, поведение не изменилось.
- CI: `.github/workflows/ci.yml` — `./gradlew test` на JDK 17 (push + PR).

## 0.4.0 — 2026-07-27

Паритет iOS SDK 0.4.x (WEB-814):

- `openWebPaywallById` / `openWebPaywallEmbeddedById` — открытие пейволла по ID
  из кабинета (резолв публичного URL через `GET /public/paywall-url/:paywallId`).

  `Pending` (окно истекло, доступ может доехать позже).
